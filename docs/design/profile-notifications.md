# Profile and account notifications

The profile continues Reunite's Agent Honk direction: quiet white forms, a compact warm identity/photo strip, the supplied palette and Outfit/Noto Sans Thai. The tall membership card and numbered section badges are removed. Name, education and contact information form three scannable sections, with section headings beside the fields on desktop and above them on mobile. The avatar initial now scales with its size. Photo controls have 44px targets and concise format/size guidance. The account button uses natural text width, and the Footer keeps only its brand signature.

`ProfileExperience` composes `ProfileIdentity` and `ProfileForm`; `useProfileEditor` retains validation, save/upload lifecycle and existing API behavior. Internal dashboard/profile links use Next Link; campus links retain full-document navigation for their geolocation policy. The form's sticky action bar reserves feedback space, keeps typed values during errors and animates actual pending/success/error changes using Motion. Email-password confirmation expands in place with reduced-motion support. A real request blocks overlapping saves/uploads; no fake progress or delay is added.

`ProfileSkeleton` matches the ready strip and the actual 2/4/2 field groups. Photo upload has its own wave placeholder. `ProfileAvatar` keeps a fixed-size Skeleton until the real image loads, then crossfades it; failed images fall back to the proportional initial. Device reduced motion removes transitions and continuous waves, while the shared pause state controls them in the shell. Browser tests hold actual upload/image requests and introduce read latency only in the disposable test schema to verify these states.

The bell sits beside the existing motion control. Its badge is the server's unread count, capped visually at 99+. A focus-managed MUI Popover shows genuine account events, local Thai timestamps, a useful empty state, Skeleton during the initial request, retry on failure, pagination and a separate “อ่านทั้งหมด” action. Opening the panel does not silently mark notifications as read. Escape and click-away close it and restore focus. Reduced motion disables entry transitions; the shared motion preference controls portal Skeleton movement. Refresh occurs on opening, window focus, successful account edits and every 60 seconds while visible; this is polling, not push delivery.

The profile saves text explicitly. Photo selection saves immediately, as stated beside its picker. Upload/save controls prevent overlapping mutations, show bounded pending feedback, preserve typed form values on errors and display returned server state. A native unload prompt protects unsaved text edits. Changing the login email requires the current password; the interface does not claim email verification. Forms are labeled, errors are local and announced, and the server page guard protects private data before rendering. Route Skeletons reflect real loading with no artificial minimum delay.

Notifications currently cover only successful profile and avatar changes. There is no announcement composer, email/push delivery, fabricated activity, unread demonstration data or invented claim/matching trigger. Image attachment in this revision means the requested personal profile photo, not an unrequested notification publishing workflow.

They inform visual review, consistency and accessible interaction; no external design scripts were installed. Upload handling follows the selected controls in [OWASP File Upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) and [sharp's input documentation](https://sharp.pixelplumbing.com/api-constructor/). This is implementation guidance, not an enterprise or accessibility certification.

Validation uses an isolated PostgreSQL schema and real production standalone server. Browser coverage includes private route guards, persisted profile data, image upload and reload, loading/empty/failure/retry notification states, unread/read persistence, keyboard focus, responsive overflow, reduced motion and selected automated WCAG A/AA rules. Physical-device testing, deployment CI and organization-specific policies remain separate release work.

The latest copy revision removes the three section explanations and optional-data note, along with the idle privacy/lock caption. Section headings and input labels remain. Unsaved, saving, success and error feedback still appears when relevant; the feedback region reserves its geometry. Section Skeletons no longer include explanation lines.
