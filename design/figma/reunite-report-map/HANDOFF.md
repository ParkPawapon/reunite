# Reunite — แจ้งสิ่งของและแผนที่บางมด

ขอบเขต: Figma Design สองหน้า พร้อมหน้าจอย่อยสำหรับแต่ละสถานะ ชุด Components และ Prototype สำหรับตรวจการใช้งาน อ้างอิงเว็บ Reunite ที่มีอยู่ ณ 16 พฤศจิกายน 2569 ไม่เปลี่ยน API หรือฐานข้อมูลในการส่งมอบแบบครั้งนี้

## 1. หน้าแจ้งสิ่งของ

แท็บ **ของหาย** ใช้ `type: LOST` และแท็บ **ของที่พบ** ใช้ `type: FOUND` ใช้โครงฟอร์มเดียวกัน เปลี่ยนคำถามสถานที่และวันเวลาตามแท็บ เก็บข้อมูลที่ผู้ใช้กรอกเมื่อสลับแท็บ

| ข้อมูลบนหน้า        | API               | เงื่อนไข                                                                                 |
| ------------------- | ----------------- | ---------------------------------------------------------------------------------------- |
| ชื่อสิ่งของ         | `title`           | บังคับ ตัดช่องว่างหัวท้าย 1–255 ตัวอักษร                                                 |
| หมวดหมู่            | `categoryId`      | บังคับ ใช้ ID จาก `GET /api/v1/categories`                                               |
| สถานที่หาย/พบ       | `locationId`      | บังคับ ใช้ ID จาก `GET /api/v1/locations`                                                |
| วันและเวลาเกิดเหตุ  | `eventDatetime`   | บังคับ ISO 8601 พร้อม timezone เช่น `2026-11-16T10:30:00+07:00` ไม่ใช่เวลาที่สร้างประกาศ |
| รายละเอียดเพิ่มเติม | `description`     | ไม่บังคับ ไม่เกิน 10,000 ตัวอักษร                                                        |
| รูปสิ่งของ          | แยกขั้นตอนอัปโหลด | 1 รูป JPEG, PNG หรือ WebP ไม่เกิน 5 MiB                                                  |

เมื่อส่ง ให้ตรวจข้อมูลก่อนเรียก `POST /api/v1/item-reports` ผู้แจ้งมาจาก session ของระบบ ไม่เพิ่มช่องกรอกผู้แจ้งหรือสถานะของรายงาน หลังได้ `id` จึงเรียก `PUT /api/v1/item-reports/:id/image` หากแนบรูปไว้ การอัปโหลดรูปไม่สำเร็จต้องเก็บรายงานที่สร้างแล้ว และลองแนบรูปใหม่เฉพาะรายการนั้น ห้ามสร้างรายงานซ้ำ

สถานะในแบบ: แบบเริ่มต้นทั้งสองแท็บ, กรอกข้อมูลแล้ว, ช่องข้อมูลผิด, แนบรูปแล้ว, กำลังส่ง, ส่งสำเร็จ และส่งไม่สำเร็จ การคลิกใน Prototype ใช้ข้อมูลตัวอย่าง ไม่ได้กรอกหรือบันทึกลงฐานข้อมูลจริง

**ความสัมพันธ์กับ component ใน repo:** ใช้รูปแบบ MUI field/button และสีจาก `apps/web/src/theme/colors.json` ฟอร์มใหม่ควรอยู่ใน feature item-reports; validation อ้างอิง `apps/web/src/modules/item-reports/presentation/schemas.ts` ส่วน AppShell, Sidebar, Topbar และ Footer ใช้ `apps/web/src/components/shell/` ชุดเดิม ชื่อใน Figma เป็นชื่อสำหรับแบบ ไม่ได้หมายความว่ามี React component ของฟอร์มใหม่นี้ครบแล้ว

## 2. หน้าแผนที่

ค้นหาด้วยรหัสหรือชื่ออาคาร → เลือกจุดหมาย → เลือกต้นทาง → ดูระยะทางและเวลาเดิน → เริ่มเดิน → ถึงบริเวณจุดหมาย มีหน้าจอสำหรับไม่พบผลการค้นหา ไม่พบเส้นทาง และไม่อนุญาตตำแหน่ง

รูปทรงอาคารและเส้นทางมาจาก `anchors.generated.json` ใช้กราฟและ `findWalk` ใน `walking.ts` ของ repo เส้นทางตัวอย่าง **N7 → S3 = 358.7257 เมตร** แสดงประมาณ **360 เมตร / 5 นาที** คิดด้วยความเร็วสมมติ 1.25 เมตร/วินาที ปัดเวลาเดินขึ้น ไม่รวมสัญญาณไฟ การรอ หรือการเดินในอาคาร

**ข้อมูลที่ยังต้องยืนยัน:** ปลายทาง N7 เป็นจุดเข้าใกล้อาคาร (`approach`), S3 เป็นประตูที่มีในข้อมูลแผนที่ (`mapped-entrance`) ทั้งสองยังต้องตรวจหน้างาน ก่อนรับรองการนำทางถึงประตูจริง แบบนี้ไม่รองรับชั้นและห้อง ไม่สร้างเส้นตรงลัดผ่านอาคารหรือสมมติทางเดินเพิ่ม

จุดสีน้ำเงินใน Prototype เป็นตัวอย่างจำลอง ระบบจริงต้องใช้ Geolocation ที่ผู้ใช้อนุญาต แสดงรัศมี accuracy จากค่าที่ได้รับ และมีทางเลือกเลือกอาคารต้นทางเองเมื่อปฏิเสธหรือหาตำแหน่งไม่ได้ ห้ามแสดงตำแหน่งหรือทิศปลอม หยุดติดตามเมื่อออกจากการนำทาง

แผนที่ใช้ข้อมูลเปิดที่มีอยู่ใน repo ไม่ใช้ภาพดาวเทียม Google Maps หรือแผ่นภาพจาก Google เป็นพื้นหลัง ไม่มี API key หรือบริการเสียเงินในชุดแบบนี้ คงเครดิต OpenStreetMap/Overture และ `source-notice.txt` ไว้กับข้อมูลที่เผยแพร่ ชื่อ/ตำแหน่งอาคารอ้างอิงงานสำรวจใน repo ไม่ใช่ข้อมูลรังวัด

| Icon button     | Default, Hover, Pressed, Focus, Disabled, Loading                     | เป้ากด 44×44 px มี aria-label และ tooltip             |
| Field           | Default, Hover, Focus, Filled, Error, Disabled, Loading               | ใช้ label อยู่เสมอ แสดง error ใต้ช่อง                 |
| Select          | Default, Hover, Focus, Filled, Open, Error, Disabled, Loading         | ใช้ข้อมูล API; ไม่สร้าง ID เอง                        |
| Textarea        | Default, Hover, Focus, Filled, Error, Disabled                        | ข้อความไม่บังคับ; ไม่แสดง HTML จากผู้ใช้              |
| Report tab      | Default, Hover, Pressed, Focus, Selected, Disabled × Lost/Found       | สลับ tab ด้วยเมาส์และคีย์บอร์ด; คงค่าที่กรอก          |
| Navigation item | Default, Hover, Pressed, Focus, Active                                | ใช้ nav component เดิมและ `aria-current`              |
| Upload          | Empty, Hover, Drag over, Uploading, Attached, Error, Disabled         | 1 รูป มี preview, เปลี่ยนรูป, ลบ และลองใหม่           |
| Location result | Default, Hover, Focus, Selected                                       | ชื่อและรหัสอาคาร; ใช้รายการค้นหาร่วมกัน               |
| Banner          | Information, Success, Warning, Error                                  | ข้อความสั้น บอกปัญหาและทางแก้                         |
| Map pin         | Default, Hover, Selected                                              | ชื่อสถานที่ไม่ขึ้นกับสีอย่างเดียว                     |
| Live location   | Following, Low accuracy, Permission denied                            | ต้องแสดง accuracy จริงจากอุปกรณ์                      |
| Skeleton        | Quiet, Shimmer                                                        | รักษาขนาด content; reduced-motion ใช้ Quiet           |

ฟอนต์ **Outfit** สำหรับตราและตัวเลข; **Noto Sans Thai** สำหรับภาษาไทย สีหลักใช้ KMUTT Orange `#FA4616`; ปุ่มหลัก `#C83A13`; Hover `#A32E10`; Sidebar `#682511` พื้นหน้า `#F8F9FA` ไม่เพิ่ม palette ใหม่ให้หน้าหลัก สีแผนที่ที่เพิ่มเป็นสีเพื่อแยกประเภทพื้นที่ และมีชื่อกำกับ

## Motion และ accessibility

Hover/Pressed 120 ms, เปลี่ยนหน้า 180–240 ms, Skeleton 1.3 s (วงรอบ ไม่ใช่เวลาหน่วงโหลด) ใช้ `prefers-reduced-motion` ลดเป็นเปลี่ยนทันทีหรือ fade สั้น Focus ต้องเห็นชัด มี label/ข้อความสถานะ ไม่มี animation กะพริบหรือกล้องเคลื่อนอัตโนมัติ

ก่อนนำไปพัฒนา: ทดสอบ tab order, screen reader, error focus, touch target, layout มือถือ และการบันทึกรายงานกับรูปจริงอีกครั้ง การตรวจแบบหรือ Prototype ไม่ใช่ผลผ่านของระบบ Production

## ไฟล์ในชุด

- `design-model.json`: โครงหน้าจอ สถานะ สี ฟอนต์ และข้อมูลแผนที่สำหรับสร้างเลเยอร์
- `preview.html`: ตัวอย่างตรวจหน้าจอแบบคลิกเปลี่ยนสถานะได้ เปิดผ่าน static server; ไม่เชื่อม API/GPS
- `import-to-figma.js`: สคริปต์สำหรับ Figma Plugin API สร้างเลเยอร์ Components ตัวแปร และ Prototype
- `source-notice.txt`: แหล่งข้อมูลและเงื่อนไขแผนที่เดิมของโครงการ

รันสคริปต์นำเข้าบนไฟล์งานใหม่เท่านั้น สคริปต์จะสร้างหน้าของงานนี้เพิ่ม และจะหยุดหากพบชื่อหน้าของชุดเดิม เพื่อป้องกันการสร้างซ้ำหรือเขียนทับงานเดิม
